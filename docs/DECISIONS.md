# TCGEmpire — Decisions (ADR log)

Short records of decisions that are expensive to change. New decisions are appended; a changed decision
gets a new entry that names the one it replaces. Status: **accepted** unless marked otherwise.
The owner approved the plan with answers on 21 Nov 2026 (`/USER_QUESTIONS.md`).

| # | Decision | Reason | Consequence / fallback |
|---|----------|--------|------------------------|
| 001 | The client is a **Vite + React + TypeScript single-page app**, hosted as static files on Vercel. | Fully behind login, client-heavy and animated; server rendering adds cost and pitfalls without benefit. Static hosting cannot exceed Hobby function limits. | No server-side secrets in the frontend. Anything privileged lives in the database. |
| 002 | **All game logic lives in Postgres functions** (PL/pgSQL), called as RPCs. | Free plan has no RPC invocation limits; transactions and locking for free; no cold starts; one authoritative place. | SQL volume is high; mitigated by engines, templates and tests. |
| 003 | **Rules are implemented once.** The client never recomputes outcomes or costs; it shows what RPCs return. | Two implementations of a rule drift apart and show players wrong numbers. | Previews are RPC answers. Offline/dev play uses the same SQL (ADR-008). |
| 004 | Money is `bigint` **cents**, sent as JSON numbers, capped at 9 × 10¹⁵; rates in basis points; no floats stored. | Exactness in SQL and in the browser without BigInt handling everywhere. | The Preisniveau is capped at ×250 so balances stay in range. Lifting the cap later means switching the one `Money` type to strings. |
| 005 | **Open economy with a full ledger**: every money change goes through one function with a reason code. | Sources and sinks must be measurable to balance an incremental game. | Admin console and simulation read the same reason codes. |
| 006 | *Replaced by 026.* (No inflation, real-world price scale.) | — | — |
| 007 | **Lazy timers** for everything idle; **one tick dispatcher** per minute for the few clock-driven systems, each isolated with catch-up caps. | Nano compute is small; idle players must cost nothing; one failing system must not stop the rest. | Tick duration and errors are logged and shown to the admin. |
| 008 | **Tests and local play run the real SQL in PGlite**; the app has a local mode without Supabase. *Spike in alpha_01.* | Fast dev loop without Docker; e2e without a backend; no second implementation. | Fallback: Postgres binaries + PostgREST locally. |
| 009 | **Polling `sync` call + Realtime Broadcast as enhancement.** | Works even if Realtime is unavailable; keeps the message budget safe. | Countdown timers use the server clock offset. |
| 010 | **Content as code**: TypeScript data in `content/` → generated seed → `content.*` tables; admin overrides stored separately. | One place to edit; typed; shared by client and server; deploys never wipe live tuning. | Seed applied only when its hash changes. |
| 011 | **Inventory model**: bulk cards as stacks, hits and slabs as individual copies with hidden quality values. | Small database, yet every valuable card has an identity. | A bulk card becomes a copy when graded. |
| 012 | **Pixel art is code**, rendered at build time into PNG atlases; own painter toolkit with a mandatory visual review loop. | "All art generated by code" at high quality needs tooling and eyes on the result. | Atlases are build outputs; art source is lazy-loaded per set. |
| 013 | Card text is drawn with **own bitmap fonts inside the image**. | Authentic pixel look; cards are shareable images. | Automatic condensing for long German names. |
| 014 | **German** for all player-facing text; **English** for code, comments, commits and docs. | Friends are German; tooling works best in English. | Texts live in typed message modules, never in components. |
| 015 | **Username + password + one shared invite code** (set once, reusable, stored hashed, changeable by the admin); no e-mail flows. | Owner decision Q-4. Zero setup for friends; keeps strangers out. | Join attempts are rate-limited. |
| 016 | Clients have **no table access**: only schema `api` is exposed; RLS on with no policies everywhere. | Smallest attack surface; no policy maintenance. | Reads are RPCs returning page documents. |
| 017 | **No Postgres enum types**; text + check constraints. | Enum values cannot be used in the transaction that adds them. | — |
| 018 | **Injectable clock and seedable randomness** in SQL. | Deterministic tests; accelerated simulation; no time-of-day flaky tests. | `now()` and `random()` are never called directly in game functions. |
| 019 | **Migrations via Supabase CLI from CI**, one transaction per file, tests first. | A proper migration ledger from day one; no manual copies. | Fallback: generated SQL file for the SQL editor. |
| 020 | **Version scheme**: `0.0.1-alpha_NN` per milestone until the full release `0.0.1`. | Owner's rule. | Changelog entry and in-game patch notes per alpha. |
| 021 | **Real brands and public figures as private parody**, under the house rules in `HUMOR.md` §2; all names swappable in content. | Owner's wish; the game is private. | The site is `noindex`; no public distribution. |
| 022 | **Desktop-first**, responsive down to 390 px without being designed for phones. | Owner's wish. | Mobile polish is not a release criterion. |
| 023 | **Set lifecycle is manual.** No set enters or leaves print automatically. | Owner's rule. | Admin console action + audit log. |
| 024 | **Attacks are capped and blockable**: one roll `base + Angriff − Abwehr`; Abwehr from account upgrades, Angriff from skills; daily loss cap 10 % of net worth without the collection; only uncollected bunker money is stealable. | Owner decision Q-7: medium intensity with a real chance to block. | All values in config. |
| 025 | Sets are curated to **~85–90 cards** with the game's own seven tiers; every beloved card stays. | Owner's 30–100 rule; art effort; long collection chase. | Lists in `docs/sets/`. |
| 026 | **Own price scale with a slow Preisniveau.** Prices start ~20× real life (booster 100 €); incomes grow ~×2.000 per run; a server-wide factor `P = min(250, 1.018^max(0, C_med − 20))` multiplies every game-set amount, updated daily. Config holds Basis-€; `private.eur()` converts. Replaces 006. | Owner decision Q-11: an economy between real life and idle-game inflation. Keeps cards economically relevant at every stage and lets numbers grow across prestiges. | Balancing is done in Basis-€. One config value switches inflation off. |
| 027 | **Level 100 in about 2–3 weeks**: `minutes_for_level(n) = 0.5 + 0.17 × n^1.3`; feature unlocks re-spaced (Firma at 30, dark side at 35, prestige at 100). | Owner decision Q-6. | Tuned by the simulation. |
| 028 | **The first account created is the admin** and plays normally; if deleted, the oldest remaining account becomes admin. | Owner decision Q-5. | — |
| 029 | **Gefahrenzone**: players can reset or delete their account. Items are destroyed, open business is cancelled, old entries are anonymised; reset has a 24 h cooldown. | Owner requirement. Destroying items prevents wealth laundering. | Supply and Pop Report shrink accordingly. |
| 030 | **Multi-pack buying and opening (1/5/10) and instant reveal are available from level 1**; only display mode (×36) is an upgrade. | Owner requirement. | The server returns all packs of a batch in one answer. |
| 031 | **Pixel-art budget**: full effort only for cards and products; elsewhere a small fixed set (icons, bunker stages, generated emblems); no avatars, room scenes or portraits in 0.0.1. | Owner requirement: keep production effort and token use where it matters. | Profile pictures are card artworks; housing is a list UI. |
| 032 | **Tone**: dark humour and hard swearing allowed; the game roasts in-game behaviour; no slurs about protected traits, no party politics, real people only in their public role; no insider content. | Owner decision Q-8. | `HUMOR.md`. |
| 033 | **Daily reset 00:00 Europe/Berlin**; weekly Monday 00:00. | Owner decision Q-22. | Daily tick system is idempotent per day. |
| 034 | **Event cadence**: one Tagesereignis per day, random small events, 2–3 announced Highlight-Events per week. | Owner decision Q-18. | Schedule values in config; admin can trigger anything. |
| 035 | **Designed for 2–10 players.** NPC traders, rivals and battle bots carry the world when few humans are online; shared store stock scales with active players. | Owner decision Q-3. | Every feature is tested with two players. |
| 036 | **Build lean.** Smallest implementation that meets the design; generic data-driven engines over one-off code; no speculative abstractions, flags or config nobody asked for; tests focus on money/item invariants and RPC contracts; few screenshots. | Owner requirement: efficient on development time and tokens. | Rules in `AGENTS.md` §4. |
| 037 | **Prestige is not a shortcut back to wealth**: cash and progress reset; the kept collection returns from the attic only within storage and a daily retrieval limit; modest perk multipliers. | Owner decision Q-12. | Simulation target in `ECONOMY.md` §11. |
| 038 | **Own login on top of anonymous Supabase sessions.** Supabase gives each browser an anonymous auth user; `join` / `login` / `logout` bind it to a player. Passwords are bcrypt hashes in `game.credentials`; wrong passwords are counted and lock the account for minutes. Refines 015. | No synthetic e-mail addresses (which hosted Supabase may reject), no e-mail flows, account deletion without touching Supabase's auth tables, identical behaviour in local mode. | The owner must switch on "Anonymous sign-ins" once (`docs/SETUP.md`). |
| 039 | **The API schema is `public`** (functions only); tables live in `game`, helpers in `private`. Every RPC is passed through `private.expose()`, which revokes it from `anon`/`public` and grants it to `authenticated`. Replaces the `api` schema of the plan. | `public` is exposed by default, so no project setting has to be changed; a test asserts that no function is callable by `anon` and that each has a contract. | — |
| 040 | **Own minimal migration runner** (`scripts/db-migrate.sh`, psql, one transaction per file, ledger table `private.migrations`) instead of the Supabase CLI. Replaces 019. | One secret, no CLI behaviour to depend on, and the same script was verified against a real Postgres 16. | The content seed is applied on every deploy (idempotent upsert). |
| 041 | **React Router** (declarative routes) instead of TanStack Router. | Smaller surface and less ceremony for ~25 simple pages; "build lean". | — |
| 042 | **Local mode verified**: the unchanged migrations run in PGlite (Node tests and in the browser) and on Postgres 16. Spike of 008 closed. | — | — |
| 043 | **Art detail only for Ultra and Grail.** These two tiers are individually crafted; Common to Alternative use simple template art produced in batches with one review per batch. Refines 031. | Owner decision of 22 Nov 2026: saves development time and tokens; the chase cards are where players look. | Holo and Alternative are distinguished by frame treatment and foil. Alpha_01's sample shrinks to two detailed cards plus the existing lower-tier ones. |
| 044 | **Reusable slab per grading company.** The slab image is a frame without text or card (`slab-psa`, `slab-bgs`, `slab-cgc`, `slab-company`); the client places the card sprite inside and writes card name, set, grade and cert number as normal DOM text on the label. | Owner decision 22 Nov 2026: no pixel slab per graded card; saves art work and tokens. | Geometry in `art/products/slab-geometry.ts`, shared by art and client. |
| 045 | **One card back for every card in the game** (all four TCGs): product `card-back`. | Owner decision 22 Nov 2026. | — |
| 046 | **Reusable card model below Ultra.** All Common to Alternative cards are generated from a compact data spec (archetype, palette, parts, scene) by the kit in `art/kit/`; only Ultra and Grail get bespoke draw code. Existing hand-made lower-tier cards stay. Refines 043. | Owner decision 22 Nov 2026: reuse as much as possible to save time and tokens. | A new lower-tier card costs one data line plus a batch review. |
| 047 | **Card catalog lives in `content/`** (`content/sets/*.ts`, `content/catalog.ts`); card values are calibrated at build time so an average booster is worth 72 % of its list price, then seeded. Art imports names and tiers from there. | One source for game data and art; values stay testable. | Runtime value = seeded base × Preisniveau (market factors follow in alpha_04). |
| 048 | **Quest, stamp and achievement EP is a share of the current level** (`private.ep_share`); action EP (boosters, minijobs, shifts) stays in fixed level-1 units. Level rewards shrink to 8 minutes of reference income. | The simulation showed fixed quest EP flooding early levels (level 20 in six minutes) and starving mid levels. Metric moved: time to levels 10/20/30 (now 12 min / day 2 / day 3). | `sim/pace.test.ts` keeps the pace within bands. |
| 049 | **Balancing simulation** (`sim/`): a bot plays the real SQL in PGlite with a fast-forwarded clock, 150 active minutes per day; reports the pace table and income mix. | Measure instead of guess (ECONOMY §13). | ~15 s per simulated 3 days; runs in CI as a test with wide bands. |
| 050 | **Bunker upgrades pay out the bunker first.** | A new rate or capacity must not apply retroactively to time already passed. | — |
| 051 | **Account reset destroys the player's items and ledger rows**, keeps daily ledger totals; deletion cascades and anonymises feed entries. | Owner requirement (Gefahrenzone) without wealth laundering. | 24 h reset cooldown. |
| 052 | **Feature tours, NEU badges and read patch notes are remembered per device** (settings store in the browser), not on the server; the planned `tour_seen` RPC is dropped. | A tour shown once more on a new device costs nothing; saves an RPC, a column and a contract. | Every level unlock must name its page and tour (`FEATURE_PAGE` in `src/app/nav.ts`, `texts.tour.features`); the types fail otherwise. |
